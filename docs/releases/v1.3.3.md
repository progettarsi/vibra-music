# vibra 1.3.3

## Changes

- Cover artwork and its blurred extension form one continuous field, with softer shading on bright covers.
- Artwork and backdrop travel together between the full player and mini-player, using the same geometry in both directions. Cropping begins halfway through closing and remains inside the player shape.
- The mini-player silhouette follows a continuous rotation phase while the artwork stays upright.
- Music videos fade into the original cover during closing. Opening reverses this transition when a video frame is ready; late or failed video frames retain the cover.

## Verification

The player implementation was checked on an Android 16 emulator: 146 unit tests, 202 intermediate poses in both directions, gesture reversals, predictive-back cancellation, reduced motion, battery saver and local video readiness/failure cases. The approved open-player artwork was preserved in a same-session image comparison.

These animation checks used the debug build. Release and debug builds passed, along with all 146 unit tests and release lint checks. The signed release was installed over 1.3.2 on the emulator: signing identity and existing song state were retained, and the player opened and closed without crashes. Release versionCode is 17. Physical-phone and real YouTube-video checks remain outstanding. Android versions below 12 and landscape retain the previous rendering path.

The debug-only activities and fixture assets under `app/src/debug` do not ship in the release APK. The frame extractor is an offline QA utility, not part of playback or rendering.

## Build

JDK 21 and the Android SDK with platform 37.2 are required:

```sh
./gradlew :app:assembleGmsMobileUniversalDebug :app:testGmsMobileUniversalDebugUnitTest
./gradlew :app:assembleGmsMobileUniversalRelease
```

Release signing must use your own local configuration as described in [SETUP.md](../SETUP.md). No signing material is included in the repository.
