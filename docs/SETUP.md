# Vibra — Setup, build and configuration

## Requirements

| Tool | Version used for the verified build |
|---|---|
| JDK | Temurin 21.0.12 (JDK 21 is required: `jvmTarget = 21`) |
| Android SDK platform | `platforms;android-37.2` (`compileSdk 37`, minor 2) |
| Build tools | 37.0.0 |
| NDK | 30.0.16248370 (only used for stripping native libs) |
| Gradle | 9.8.1 via the wrapper (`./gradlew`) |
| Android Gradle Plugin | 9.4.1 · Kotlin 2.4.21 · Compose 1.13.0-beta01 · Material 3 1.5.0-beta01 · Media3 1.11.1 |

Android Studio is optional; the command line is enough.

## First-time setup

```bash
# 1. local.properties (never commit it). Forward slashes avoid escaping issues on Windows.
echo 'sdk.dir=C\:/Users/<you>/AppData/Local/Android/Sdk' > local.properties

# 2. Optional secrets / integrations (all optional, see table below)
#    LASTFM_API_KEY=…  LASTFM_SECRET=…  DISCORD_APPLICATION_ID=…  TOGETHER_BEARER_TOKEN=…
```

## Build variants

Flavour dimensions: `distribution` (`gms` | `foss`) × `device` (`mobile` | `tv` |
`automotive`) × `abi` (`universal` | `arm64` | `armeabi` | `x86` | `x86_64`) × build type
(`debug` | `release` | `nightly` | `benchmark` | `nonMinifiedBenchmark`).

Recommended for a phone: **`gmsMobileUniversalDebug`** (Cast + Google sign-in helpers;
runs on emulators and on arm64 phones). `fossMobileArm64Debug` is a smaller APK without
Google Play Services dependencies.

```bash
./gradlew :app:assembleGmsMobileUniversalDebug
# → app/build/outputs/apk/gmsMobileUniversal/debug/app-gms-mobile-universal-debug.apk
```

### Installing

```bash
adb install -r app/build/outputs/apk/gmsMobileUniversal/debug/app-gms-mobile-universal-debug.apk
```

or copy the APK to the phone and open it (allow "install unknown apps" for your file
manager). The debug build installs as **VIBRA Debug** (`vibra.music.com.debug`) next to
any other app.

### Release builds

Use your personal release signing configuration described in [personal signing and performance](#release-signing-and-performance). No keystore is generated by these instructions. The upstream ArchiveTune keystore must never be used.

```bash
./gradlew :app:assembleGmsMobileArm64Release
```

## Runtime configuration

| Feature | Needs | Default in this repository |
|---|---|---|
| Streaming, search, home feed, lyrics providers | Network (public YouTube Music / lyrics endpoints) | Works without an account |
| YouTube Music account library, liked songs, playlist sync | Sign in from Profile → "Login" (in-app WebView login) | Signed out |
| Local audio playback | Grant "Music and audio" permission (Profile → On this device) | Asked on demand |
| Last.fm scrobbling | `LASTFM_API_KEY`, `LASTFM_SECRET` in `local.properties` or env | **Disabled** (no keys shipped) |
| Discord Rich Presence | Removed | Not available |
| In-app updater | A release repository of your own (`GITHUB_OWNER`/`GITHUB_REPO`) and `UPDATER_AVAILABLE=true` | **Disabled** |
| Gatekeeper / data server | — | Disabled (upstream service) |
| AI lyrics translation / AI content filter | User-entered API key in Settings → AI integration | Off until configured |

## Release signing and performance

Release signing is read from environment variables, then ignored `local.properties`:

| Environment | local.properties |
| --- | --- |
| `VIBRA_KEYSTORE_PATH` | `signing.storeFile` (absolute path, preferably outside this checkout) |
| `VIBRA_STORE_PASSWORD` | `signing.storePassword` |
| `VIBRA_KEY_ALIAS` | `signing.keyAlias` |
| `VIBRA_KEY_PASSWORD` | `signing.keyPassword` |

No keystore is supplied or generated by this setup. Do not commit signing files or values.
Release signing validation fails with an explicit setup message if any field/file is missing.
Debug builds use the existing Android debug signing configuration.
`benchmark` copies release optimizations but uses debug signing and `.benchmark` application ID.
`nonMinifiedBenchmark` disables R8/resource shrinking to collect unobfuscated profile rules.
Both test-only target variants expose shell profiling; no Android permission was added.

The optional `:baselineprofile` module uses Macrobenchmark directly (no Gradle profile plugin).
Enable it with `-PenableBaselineProfiles=true`. It needs its Maven dependencies on first use. Use API 34+ to preserve the seeded queue/onboarding through compilation resets; profile collection otherwise requires API 33+, or a rooted API 28+ device.
The default app build does not resolve that device-only toolchain. The test APK is self-instrumenting so it can kill and restart the target. The full interactive journey contributes to the Baseline Profile, not the startup-only DEX layout profile.

1. Build/install `:app:assembleGmsMobileUniversalNonMinifiedBenchmark`.
2. Complete onboarding by skipping sign-in and seed a playable queue in `vibra.music.com.benchmark`.
   The generator deliberately fails when the queue/search journey is unavailable; it does not
   silently generate a startup-only profile and call the full journey verified.
3. Run `./gradlew -PenableBaselineProfiles=true :baselineprofile:connectedNonMinifiedBenchmarkAndroidTest`
   with `-Pandroid.testInstrumentationRunnerArguments.class=app.vibra.benchmark.BaselineProfileGenerator`.
4. Copy the generated human-readable baseline profile from the connected test output into
   `app/src/main/baseline-prof.txt` (and the startup profile, if generated, into
   `app/src/main/startup-prof.txt`). Inspect the actual output paths printed by the runner.
5. Build `:app:assembleGmsMobileUniversalBenchmark` and run
   `:baselineprofile:connectedBenchmarkAndroidTest` with runner class
   `-Pandroid.testInstrumentationRunnerArguments.class=app.vibra.benchmark.StartupBenchmark` and the same `-PenableBaselineProfiles=true` flag.
   The profile-required case fails if no packaged profile is available. On an emulator only, add
   `-Pandroid.testInstrumentationRunnerArguments.androidx.benchmark.suppressErrors=EMULATOR` to opt into diagnostic timings; these do not represent phone performance.
6. On the same emulator, compare debug and benchmark cold starts using ten repetitions of
   `adb shell am force-stop PACKAGE` then
   `adb shell am start -W -n PACKAGE/moe.rukamori.archivetune.MainActivity`.
   Record every `TotalTime`, median, build revision, AVD/API, queue/onboarding state and compilation mode.
   Do not compare the two package IDs without completing the same onboarding/fixture setup.

Profiles and timing numbers are not checked in until they are actually generated/measured.
ProfileInstaller 1.4.1 is explicit in app dependencies. R8 is enabled for release/benchmark;
legacy conservative Media3/Guava/Ktor keep rules remain pending runtime testing rather than
being removed speculatively. Hilt/Room ship consumer rules; serialization companion rules remain.
The `@JavascriptInterface` login bridge is protected by the optimized default Android rules.

References: [Android profile collection](https://developer.android.com/topic/performance/baselineprofiles/manually-create-measure),
[Benchmark releases](https://developer.android.com/jetpack/androidx/releases/benchmark).
